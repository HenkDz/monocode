# Quarantined missing digest recovery proposal

The repaired missing-source guard distinguishes known absent/stale authority from an unreadable retained decision. Quarantined references now fail visibly instead of being silently retired, but an old unacknowledged CC5D receipt can prevent the ordinary re-raise event and unrelated reports from progressing.

Proposed narrow completion: before retiring any quarantined V2 reference, queue an ordinary CC5D recovery notice with a deterministic ID bound to the exact receipt/event IDs, verify its exact saved body/signature by control_load, and recheck the receipt, owner, recipient generation/account/home. Only then explicitly retire those old V2 IDs with the existing retiredEventIds path; never acknowledge them as consumed. The next normal digest delivers the visible notice plus retained unrelated reports. The notice says that the source is unreadable, its immutable raw record remains in Decisions, and a NEW decision ID must be raised only if current original work still authorizes it. No actor, approval, start, steer, authority, ledger or second bus is created.

Apply the same verified-notice prerequisite to both actual App acceptance and queued-consumer retirement, outside the recipient writer. Failed notice save/readback leaves the old digest visibly held, with raw quarantine and the existing trusted re-raise UI intact. Connected tests must show failed notice retains the receipt, successful notice retires only exact V2 IDs, unrelated reports/new re-raise progress, raw bytes survive reload, and no answer/goal/provider launch occurs. This is a proposal for authority review; implementation awaits root's verdict while independent N1-N5 tests continue.
