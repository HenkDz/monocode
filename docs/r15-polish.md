# R15 team map and chat polish

The Team map now occupies the main area with the sidebar visible. Opening it closes other main views; Back and Escape return to the previous content, and ordinary sidebar navigation leaves the map. Manager entry points select their project and team, with **Show whole org** clearing both scope and project. Small teams fit at a minimum of 88%; large teams may fit lower. Overflow remains reachable by panning.

The strip presents newest events first, merges consecutive events sharing their kind, agents, task and review verdict, and shows counts, actor mascots and short sentences. It includes accepted no-change tasks, closed PRs, PR readiness and review outcomes. Raw events remain separate for animation. Acceptance now retains its actual timestamp and clears it on retry or invalidation. Native and remote-host GitHub PR status retain `closedAt` for closure ordering. Historical records without those timestamps use the available acceptance or dispatch time; explicit closure messages retain their message time. Exact task IDs take priority over title matching, and ambiguous title matches retain their separate text.

Team messages render inline with their sender identity and mascot. Long messages clamp to four lines with Show more / Show less. The direction key explains assignment down, reporting up and review across; edge hover text names the current task and reporting parent. Reduced motion retains static flow indicators.

`app team.message` accepts an optional validated boolean `requiresReply`. `false` stores the message in the crew feed while skipping session creation, worker steering and recipient submission. Omitted or `true` preserves question delivery. Manager goal-progress forwarding preserves the flag. Updated prompt guidance asks agents to mark informational closure reports and acknowledgements, and avoid replies to pure acknowledgements. Text is not heuristically classified for turn suppression.

Verified causes were the modal dialog/main-view placement, unrestricted small-team fit, independent scope/filter state, missing terminal feed routes and ID-only deduplication, long-message `<details>`, and unconditional recipient delivery plus reply guidance.
